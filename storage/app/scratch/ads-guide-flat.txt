I. Project Overview
For this final project, each pair will develop a School Enrollment System. The system must demonstrate not only functional features but also the proper application of Advanced Database Systems concepts.
Your system should be designed to handle realistic enrollment situations involving multiple users, simultaneous transactions, large amounts of data, and possible database failures.
Each pair will analyze the database problems in this guide and explain how the proposed or implemented system addresses them. The focus is on database design, correctness, reliability, security, and performance.

Provide evidence that the solution works, such as screenshots, SQL output, logs, or query plans.
II. General Instructions
A. Flexible Enrollment Workflow
Your system may use a student-initiated online enrollment process, a registrar-assisted process, or a walk-in enrollment process. You do not need to add student login accounts if they are not part of your intended system. However, each enrollment must be associated with a valid student record.
A student record is different from a user account. A student record stores academic/person information; a user account provides login access; an enrollment record connects a student to a subject or section. A walk-in student may have a student record and enrollment records without having a login account.
For example, a registrar-assisted workflow may be:
The registrar searches for an existing student or creates a student record for a new student.
The registrar selects the subjects or sections requested by the student.
The system validates requirements such as prerequisites, maximum academic load, schedule conflicts, duplicate enrollment, and section capacity.
The database processes related enrollment operations safely, using transactions where appropriate.
The system confirms the enrollment only after the required operations succeed.

Use the workflow and features that your pair actually designed. Do not claim that your system has a feature that it does not have.

N/A does not automatically mean the concept can be ignored. The instructor may ask you to explain the concept or demonstrate it using a controlled database test, SQL script, or a proposed design.
Where practical, demonstrate the database-level solution, not only an application screen. Examples include constraints, transactions, locks, indexes, permissions, and recovery procedures.
Use test data. Do not expose real students' sensitive information in screenshots or presentation evidence.
C. Important Reminder
The objective is not only to create a working Enrollment System. Your pair must demonstrate an understanding of transactions, COMMIT/ROLLBACK, ACID properties, concurrency control, locking, deadlocks, constraints, indexing, query optimization, data integrity, security, and recovery.
